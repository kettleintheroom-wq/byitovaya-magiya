# Проверка PWA-прототипа

Дата проверки: 8 октября 2026. Версия приложения: 1.0.0.

## Пройдено

`node tests/content.cjs`: все 26 записей полностью совпадают с исходным контентом; все прежние календарные события сохранены при проверке 730 дат; проверены совпадение первого числа и четверга, пятница и 31 декабря. Проверены пути manifest, standalone, размеры PNG и согласованность номеров версий.

`node --check` для app.js, calendar.js, rituals.js и sw.js: ошибок синтаксиса нет.

`tests/smoke.cjs` в headless Chromium с мобильным viewport и часовым поясом Europe/Moscow:

- Четыре раздела и переходы.
- Onboarding, поиск, 26 записей в библиотеке.
- Открытие карточки, избранное, выполнение без повторной отметки в тот же день.
- Избранное, журнал и настройки после перезагрузки страницы.
- Следующий месяц и выбор 1 ноября; отображается ритуал корицы.
- Прямая ссылка на карточку ритуала.
- Manifest, доступность всех иконок.
- Реальная регистрация и управление страницы service worker; 12 ресурсов в кеше.
- Отключение сети через браузер, перезагрузка страницы, поиск и чтение журнала без сети.
- Отсутствие горизонтального переполнения при ширинах 320, 360, 390, 430, 768 и 1280 px.
- Реальный цикл обновления worker: установка новой версии, waiting, плашка, нажатие «Обновить», активация 1.0.1, сохранность журнала. Обновление моделировалось только ответами тестового сервера; исходные файлы остаются 1.0.0.
- Инструкция установки при iPhone user agent. Это проверка ветки интерфейса, а не физического Safari.
- Окно ручного копирования при отсутствии Web Share API и недоступном clipboard.
- В прогоне нет ошибок `pageerror`.

Скриншоты мобильной исходной страницы, главного экрана и календаря изучены визуально.

## Не подтверждено этой средой

Опубликованная production-страница https://bytovaya-magiya.pages.dev/ не открылась: веб-источник недоступен, облачный браузер вернул 502 / Connection refused. Сайт изучен по клонированному main и его локальному рендеру. Это не доказывает, что сайт недоступен на устройстве пользователя.

Физическая установка и standalone-запуск на iPhone и Android требуют проверки на телефонах. Preview Cloudflare и production должны пройти тот же короткий прогон после деплоя. Доступность автоматических preview зависит от настроек Cloudflare; production не изменялся.

## Запуск проверок разработчиком

Для проверки содержимого нужен только Node.js: `node tests/content.cjs`.

Для UI-проверки отдельно установить Playwright в тестовой среде и Chromium. Запуск из корня репозитория: `node tests/smoke.cjs`. Тест сам поднимает временный HTTP-сервер на 127.0.0.1:4173. Если установлен системный Chromium, передать его путь через `CHROME_EXECUTABLE`; каталог скриншотов задаётся `EVIDENCE_DIR` (по умолчанию /tmp). Не добавлять тестовые зависимости в production-приложение: у приложения нет этапа npm build.

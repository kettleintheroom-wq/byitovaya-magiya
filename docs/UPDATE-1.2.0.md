# 1.2.0 — preview Web Push, пакет для локальной публикации

Статус на 15.10.2026: владелец успешно запустил setup-скрипт на Windows и подтвердил публикацию preview 1.2.0, Worker и D1. Исходники синхронизированы с веткой pwa-prototype. Реальная доставка на iPhone и CPU на Workers Free ещё требуют приёмки; не считать push-механику принятой до ручной проверки.

Preview: https://pwa-prototype.byitovaya-magiya.pages.dev/

API: https://byitovaya-magiya-push-preview.kettleintheroom.workers.dev

В push-config.js сохранён адрес API; публичный VAPID-ключ клиент получает из /config при подписке. Закрытый ключ не переносится в репозиторий. GitHub auto-deploy использует клиент 1.2.0 из корня репозитория; локальная настройка Cloudflare не требуется для каждой сборки.

## Архитектура и данные

Существующие Cloudflare Pages + vanilla JS сохранены. Новый отдельный preview Worker + D1 + Cron. Только origin `https://pwa-prototype.byitovaya-magiya.pages.dev` разрешён клиентом и CORS; production-клиент не подключается. Нет аккаунтов, синхронизации журнала и маркетинговых пушей.

Журнал по-прежнему использует `bbm-pwa-v1`, schemaVersion 2. model.js и storage.js не изменены. Новый ключ `bbm-push-preview-v1` содержит installId, случайный 256-битный installSecret, предпочтения, личные напоминания и статус синхронизации. Он не входит в экспорт журнала. Импорт/замена журнала не затрагивает уведомления. Старые `reminders` из 1.1.0 не активируются автоматически: это была недоставляемая механика, а новые push требуют явного согласия.

На сервер не уходят журнал, избранное, статистика или onboarding. installSecret передаётся только в Authorization, на сервере хранится SHA-256. Endpoint и ключи подписки нужны для Web Push; они не выводятся в логи. Запросы ограничены 20 КБ, один custom на ritualId, до 26 custom на установку. Endpoint ограничен HTTPS-адресами поддерживаемых push-провайдеров, без редиректов. Дополнительно уникален hash endpoint.

D1-схема: `push/migrations/0001_push.sql`.

| Таблица | Данные и ограничения |
|---|---|
| installations | id PK, secret_hash, subscription, уникальный endpoint_hash, timezone, enabled, preferences JSON, updated_at, test_at |
| jobs | PK (install_id,id), kind base/custom, ritual_id, revision, spec JSON, next_at, active, outcome; индекс (active,next_at) |
| deliveries | PK (install_id,event_key), ritual_id, scheduled_at, status, created_at; индексы для близких дублей и очистки |
| guards | Короткая SQL-блокировка Cron |

Базовые предпочтения хранятся компактным JSON в installations, а фактические расписания — нормализованными строками jobs. installSecret нельзя восстановить после очистки данных сайта; это отдельная установка. Для тестирования введён технический предел 20 установок; это не обещание нагрузки или точности для 20 одновременно активных устройств.

## Личные напоминания и timezone

В подробном ритуале добавлено «Своё напоминание»: weekly (weekday + localTime) или once (date + localTime). Повторное сохранение заменяет расписание по ritualId; новая revision означает явное редактирование. Можно сохранить до разрешения push; интерфейс предупредит, что для доставки нужно подключение. Дата/время при permission flow не теряются.

При следующем запуске или возвращении в приложение синхронизируется timezone из Intl. Хранится IANA ID, не фиксированный offset. При переходе на летнее время отсутствующее weekly-время пропускается на эту неделю; once на отсутствующее время отклоняется. В повторяющийся час выбирается первое вхождение, повтор не создаётся. Завершённый once не оживает при смене timezone.

moon-core.js содержит исходную лунную формулу без изменения коэффициентов. Её напрямую используют и календарь, и Worker. Для принадлежности principal event местной дате Worker использует timezone установки; для начала waning сравниваются местные полудни двух соседних дат. Это соответствует дневным карточкам календаря. Главная страница показывает фазу на текущий момент, поэтому на дне фактического перехода до полудня её текущая фаза может ещё отличаться от календарной дневной карточки.

## Доставка и дедупликация

Cron `*/5 * * * *` (UTC) выбирает индексированные due jobs. Каждый запуск обрабатывает до 4 событий, чтобы ограничить нагрузку Free. Нормальный пилот — 1–4 устройства с небольшим числом напоминаний. При очереди точность ухудшается: задержка может превышать 5 минут. События старше 30 минут пропускаются; для once это видно как неподтверждённая доставка с предложением задать новое время. Для массового запуска нужна проверка реальной нагрузки и пересмотр scheduler; платный тариф автоматически не включается.

Перед сетевой отправкой атомарно создаётся delivery claim с ключом installId + jobId + revision + scheduledAt. Повторный Cron не отправляет тот же occurrence. Базовое и custom для одного ритуала в пределах 5 минут объединяются серверной проверкой. `tag` помогает группировать системные уведомления, но не заменяет серверную дедупликацию.

При 404/410 подписка деактивируется и endpoint очищается. При явно полученном 429/5xx допускается повтор следующим Cron в пределах окна доставки. При неопределённом сетевом результате автоматического повтора нет: иначе возможен дубль уже принятого push. Такое once не помечается успешно доставленным: UI покажет, что доставка не подтверждена. При аварии между claim и ответом также возможен пропуск. Web Push не даёт транзакционной гарантии «ровно один раз» между D1 и внешним push-сервисом.

После успешного принятия once сервером доставки он становится inactive; клиент удаляет его из активного списка при синхронизации. Технические delivery-записи очищаются через 45 дней. UI не обещает доставку при неподтверждённых изменениях offline.

Шифрование: @block65/webcrypto-web-push 2.0.0, RFC 8291 aes128gcm + RFC 8292 VAPID, включая Apple. Subject — URL preview. Названия secrets: VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY. Закрытый ключ генерируется только при локальном запуске владельцем, хранится в Cloudflare secret и исключённой из git локальной папке; в пакете ключей нет.

## Service worker и routing

Добавлены push и notificationclick. Некорректный payload показывает безопасное общее уведомление. URL из payload не принимается. Закрытая PWA открывается по `#ritual-{id}`. Уже открытая получает OPEN_RITUAL и focus; клиент проверяет id по каталогу. Исправлена гонка отложенного close-события диалога при переходе между ритуалами.

Safari navigationResponse, кеширование корня без redirected response, контроль обновления и localStorage-защита сохранены. Precache вырос с 14 до 18 файлов. Нижняя навигация по-прежнему из четырёх пунктов; #notifications относится к «Моё».

## Проверки

- 14 серверных/календарных тестов: локальные времена, конец месяца/февраль/високосный год/граница года, DST, newmoon/waning, совпадение со старым алгоритмом 732 дня в трёх timezone; авторизация/CORS/валидация; идемпотентное обновление; once/редактирование/удаление; near-dedup; отключение; 410/503/неопределённая отправка; смена timezone; реальное формирование зашифрованного aes128gcm-запроса с подменённой сетью.
- SQL выполнялся на SQLite-адаптере с той же миграцией. Миграция применена и через Wrangler к локальной D1. Это не проверка облачной D1.
- Wrangler deploy --dry-run успешно собрал Worker. Локальный dev-эмулятор не запустился: системная ошибка uv_interface_addresses в этой среде. Поэтому live HTTP-интеграция в workerd не заявляется.
- Браузерные тесты: ручной opt-in без запроса при загрузке, пять наборов, denied/iPhone Safari, weekly/once/редактирование/удаление, тестовый endpoint, выключение/unsubscribe, offline и неизменность ключа журнала. PushManager и системный permission подменены, доставки не было.
- Проверены 320/390/430/1280 px с увеличенным текстом. Обычные экраны, PNG/share/fallback, импорт/экспорт, фильтры и случайная логика проходят существующие проверки.
- Настоящее обновление клиента 1.1.4 → 1.2.0 через service worker сохранило журнал, favorites, settings, onboarded и старые reminders побайтно; следующий update/reload и offline также проверены.
- Отдельный SW-тест: payload, fallback, closed-window deep-link, open-window postMessage+focus, запрет произвольного URL.

Владелец подтвердил успешный запуск скрипта на Windows и публикацию в Cloudflare. В рабочем браузере виден клиент 1.2.0. Независимо не проверены тариф аккаунта, runtime CPU Free, реальный iPhone permission/Share Sheet и доставка через APNs. Полная приёмка — сценарий в START-HERE.md.

# «Бытовая магия» — обновление 1.1.0

Рабочий адрес: https://pwa-prototype.byitovaya-magiya.pages.dev/

Изменения относятся только к ветке pwa-prototype. Main и production не изменяются.

## Что появилось

- «Напомнить» в короткой и подробной карточках. Для недели, первого числа и Нового года — 09:00 в день ритуала или 20:00 накануне; для новолуния/полнолуния — событие или час до него; для растущей/убывающей фазы — начало фазы. Без календарного правила — выбранная пользователем дата и время. «Не напоминать» отменяет настройку.
- В «Моё» можно изменить или удалить напоминания. В интерфейсе явно указано, что уведомления пока не приходят.
- Вертикальные PNG 1080×1920: сводка дня и «Поколдовано». Второй тип доступен после отметки и для старых записей в истории; дата на картинке соответствует дате записи.
- Статистика текущего месяца по категориям. Каждая отметка считается один раз, в первой категории ритуала. Поэтому сумма категорий равна количеству «Поколдовано». Объяснение видно рядом со статистикой.
- Случайный подходящий сегодня ритуал. Контекстные приметы исключены, календарные проходят проверку даты/фазы. Следующий выбор не повторяет предыдущий, если есть альтернативы. Случайная карточка доступна на «Сегодня» и в библиотеке.
- Импорт JSON: предварительная проверка, объединение без повторов, замена с отдельным подтверждением, отмена. Старые экспорты 1.0.2 поддерживаются.

## Обновление установленного приложения

Сейчас сделай это: открой приложение с интернетом, перейди в «Моё», нажми «Проверить обновление». Когда сверху появится плашка, нажми «Обновить». В настройках должна быть версия 1.1.0. Перезапусти приложение и проверь, что сохранённые ритуалы и история на месте.

Для PWA, установленной с постоянного адреса pwa-prototype…, удалять приложение или данные Safari не нужно. Избранное, история, настройки текста и onboarding сохраняются при обновлении.

Отдельный адрес деплоя, например c8c0b6cd…, остаётся прежней сборкой. Сейчас сделай это: если приложение установлено с такого адреса и нужно перейти на постоянную ветку, сначала скачай журнал. Открой постоянный адрес в Safari, добавь его на главный экран и восстанови файл через «Моё». Это перенос между разными адресами; удалять старые данные до проверки переноса не нужно.

## Локальная модель и будущий Web Push

Ключ localStorage остаётся `bbm-pwa-v1`. Старые поля `favorites`, `log`, `settings`, `onboarded` сохраняются. Добавлены `schemaVersion: 2` и `reminders: []`. `normalise` создаёт defaults для старого состояния, отбрасывает неизвестные поля, повреждённые записи и повторы. Одна запись журнала определяется сочетанием ritual ID и локальной даты, а не временем повторного импорта.

Пример напоминания:

```json
{
  "ritualId": "coffee-cinnamon",
  "kind": "calendar",
  "timing": "eve",
  "enabled": true,
  "timezone": "Europe/Moscow",
  "localTime": "20:00",
  "updatedAt": 1791880000000
}
```

`kind` принимает calendar / phase / once. Для once добавляется `date` и выбранное `localTime`; для phase — `offsetMinutes`. Времена календарного напоминания задаются по локальному часовому поясу; если дата ритуала — 1-е число, eve означает предыдущий календарный день, включая переход месяца/года. Настройка не хранит заранее вычисленный timestamp следующего лунного события: будущий планировщик должен рассчитывать его по rule ритуала и актуальному часовому поясу.

Для одного ritualId хранится одна актуальная настройка. При объединении выигрывает более поздний updatedAt; при равенстве — импортируемая настройка. Удаление сохраняет запись с enabled:false, чтобы более старая копия не включила её обратно. В пользовательском списке отключённые записи не отображаются. Избранное и журнал объединяются без повторов; настройки интерфейса остаются текущими. При замене настройки берутся из файла.

Следующий этап, который сейчас **не реализован**: пользователь отдельно разрешает уведомления; браузер создаёт PushSubscription; Worker хранит subscription отдельно от preferences напоминаний, привязав их к устройству. Локальные reminders передаются только при включении этой функции. Планировщик читает ritualId → rule, timing, timezone, date/offset и вычисляет будущий момент; просроченные once пропускает. Отключённые записи снимают соответствующие задания. Для реальной доставки нужны серверная регистрация, хранение subscription, планировщик, ключи Web Push, обработка push в worker и ошибки/отзыв разрешения. Ни один из этих компонентов не добавлен в эту версию, разрешение уведомлений не запрашивается.

## Ограничения

- Напоминания — только локальные предпочтения, без уведомлений и фоновых таймеров.
- Данные не синхронизируются. Перенос возможен вручную через JSON.
- При импорте файл ограничен 2 МБ; неподдерживаемая более новая schemaVersion требует обновить приложение. Повреждённые отдельные записи пропускаются; файл без распознаваемой структуры или корректных записей отклоняется. Пустая настоящая копия допустима, замена всё равно требует подтверждения.
- Картинки используют системный шрифт, поэтому начертание может немного отличаться между устройствами. Размер, цвета и композиция фиксированы. Генерация без внешних изображений/шрифтов и сети.
- Реальная отправка PNG определяется поддержкой files в Web Share. Предусмотрены скачивание и текстовая отправка. Файл генерируется до отдельного нажатия отправки, чтобы не терять пользовательскую активацию Safari.
- Лунный расчёт приблизительный; случайный выбор консервативно исключает контекстные ритуалы и использует текущие календарные правила.
- Автоматические прогоны выполнены в Chromium. iPhone user-agent и макет не заменяют физический Safari/iOS standalone, системный Share Sheet и file picker — их нужно проверить по шагам выше.

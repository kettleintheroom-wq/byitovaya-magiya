# Клиент 1.3.0 — ритуалы, уведомления и настройки

Рабочая ветка — только `pwa-prototype`. Preview:
https://pwa-prototype.byitovaya-magiya.pages.dev/
Main и PR не объединяются. Реальный push и once-напоминание до этого релиза
уже проверены владельцем на iPhone. Новую навигацию iOS нужно принять отдельно
по чек-листу ниже: Chromium не заменяет физический iPhone.

## Изменения

- У detail одно главное действие: «Поколдовано». Сердечко с aria-pressed —
  в верхней панели, «Напомнить» с текущим расписанием — в блоке «Когда».
  Приглашение и PNG — спокойные текстовые действия. PNG после выполнения и
  PNG из истории сохранены, как и системный share / download / text fallback.
- В списке заголовок и свободная область карточки открывают detail. «Как это
  делается» удалено. Сердечко и «Поколдовано» имеют отдельные targets; клик
  по ним не открывает detail. Заголовок доступен с клавиатуры.
- На главной share стал текстовым вторичным действием. Календарь, контент,
  случайный выбор и схема расписания сохранены.
- В «Моё» компактные метрики и статистика без тяжёлых контейнеров. Настройки —
  строки «Уведомления», «Данные журнала», «Обновления». Экспорт/импорт и ручная
  проверка обновления переехали на соответствующие внутренние экраны.
- У активных уведомлений — master switch вместо большой кнопки отключения.
  При запрете системного разрешения показана инструкция. Пять базовых наборов
  сохранены; пользовательские напоминания открываются нажатием на строку,
  удаление находится внутри формы редактирования.
- Сохранение reminder закрывает только форму. Hash и detail сохраняются;
  появляется toast. При отключённом push он предлагает добровольный переход
  «Настроить уведомления». Редактирование/удаление также остаются в контексте.
- Preview debug-блок скрыт. Для ручной проверки открыт специальный адрес:
  https://pwa-prototype.byitovaya-magiya.pages.dev/?push-debug=1#notifications
  Он использует существующую установку, не создаёт новые ключи и сохраняет
  ограничение одного теста в минуту. В обычном интерфейсе debug не появляется.

## Нажатие push

SW получает ritualId, строит URL #ritual-{id} на своём origin. Находит
существующее окно своего scope, предпочитая focused. Если navigate доступен,
передаёт ему целевой URL; затем focus и OPEN_RITUAL. Ошибка/отсутствие navigate
оставляет focus + сообщение; второе окно не создаётся. Если окон нет —
openWindow с тем же deep-link. Client.url не используется для сравнения hash:
этот снимок может устареть после навигации внутри SPA.

Обработчик клиента закрывает вспомогательные dialogs и открывает целевой
ритуал. Для уже открытого target не создаёт ещё один detail. Сетевой/кешированный
navigationResponse с нормализацией редиректов для iOS сохранён.

Справка API: https://developer.mozilla.org/en-US/docs/Web/API/WindowClient
и https://developer.mozilla.org/en-US/docs/Web/API/Clients/openWindow

## Анонс

Отдельный локальный ключ `bbm-push-feature-intro-seen`, независимо от
Notification.permission и от версии shell. Журнал и push store не мигрируются.
Существующему onboarded-пользователю установленной PWA показывается один раз
в свободный момент. Новому — только после onboarding и следующего действия.
Пока открыта карточка/форма, показано обновление или toast — анонс ждёт.
Обычный Safari/браузер без installed/standalone его не получает.

«Не сейчас», «Настроить уведомления» и Escape отмечают показ. Выбор настройки
открывает #notifications. Разрешение запрашивается только кнопкой
«Включить уведомления» на этом экране. Сам анонс permission не запрашивает.
Флаг сохраняется между обновлениями, очищать его для обычного использования
не нужно; переустановка и очистка данных для проверки не требуются.

## Сервер и публикация

Файлы клиента публикуются обычным auto-deploy Pages из pwa-prototype.
APP_VERSION и SW VERSION = 1.3.0, все прежние ресурсы в offline-кеше.
Safe journal checkpoint перед применением новой версии сохранён.

Из backend изменены только diagnostics.js (теперь opt-in PUSH_DEBUG === 'true')
и дефолт PUSH_DEBUG: 'false' в шаблоне wrangler.json. Код редактирования
секретов, D1 bindings/схема, VAPID, Cron, endpoint, /test и sendPush не менялись.
Доставка по расписанию не требует нового Worker-кода ради клиентского UX.

Чтобы отключить временные логи на уже работающем Worker, можно задать
PUSH_DEBUG = false в Variables именно byitovaya-magiya-push-preview и применить
изменение в Cloudflare. Существующий deployed диагностический код уже
поддерживает это значение. Это публикация настройки preview Worker.

Альтернатива — обновить push/src/diagnostics.js в прежней локальной копии,
оставить wrangler.local.json с реальным DB ID, установить в его vars
`"PUSH_DEBUG": "false"` и выполнить из папки push:

```sh
npx wrangler deploy --config wrangler.local.json
```

Не заменять wrangler.local.json шаблоном с нулевым DB ID. Не запускать
start-preview.ps1 / setup-preview.mjs заново. Не выполнять secret bulk,
не генерировать ключи, не пересоздавать D1, не переустанавливать PWA.
Cloudflare-авторизации в среде разработки нет: отключение живых логов требует
действия в авторизованном аккаунте владельца. GitHub Pages deploy этого
изменения Worker сам по себе не выполняет.

## Автоматические проверки

```sh
node tests/release-config.cjs
node tests/storage.cjs
node tests/model.cjs
node tests/content.cjs
node tests/push-sw.cjs
node tests/ux-1.3.cjs
node tests/push-ui.cjs
node tests/features.cjs
node tests/smoke.cjs
node tests/ios-navigation.cjs
UPGRADE_FROM=1.2.0 node tests/upgrade-state.cjs
node tests/share-design.cjs
npm --prefix push test
npm --prefix push run check
```

Browser-тестам нужен Playwright + Chromium. Проверки update используют
зафиксированные fixtures 1.1.0/1.1.4/1.2.0. Дополнительно проверяются
1.3.0 → следующая версия, offline, snapshot журнала и push store, резервная
копия и восстановление после ошибки чтения. Разрешения/PushManager и push API
в браузерном push-тесте имитируются; это не доказательство реальной доставки.

UX-проверка: 320, 375, 390, 430 и 1280 px, обычный/увеличенный текст, основные
экраны, формы и detail без horizontal overflow и обрезанных подписей. Проверены
PNG 1080×1920, импорт/экспорт, категории, случайный ритуал и старый iOS workaround.

## Короткая приёмка на iPhone

1. Обновиться через «Моё» → «Обновления» → «Проверить обновление», затем
   «Обновить» в плашке. Проверить 1.3.0, журнал, избранное и старые напоминания.
   Если ещё открыт клиент 1.2.0, «Проверить обновление» пока находится прямо в «Моё».
2. После запуска установленной PWA дождаться анонса. Нажать «Не сейчас»;
   закрыть/открыть приложение — повторного показа нет. Обычная строка
   «Моё» → «Уведомления» всегда доступна. Второй CTA анонса проверен
   автоматически в отдельном чистом контексте; ради него не очищать журнал.
3. В ритуале создать reminder — форма закрывается, сам ритуал остаётся,
   hash не меняется на notifications. Проверить toast и подпись расписания,
   затем изменить и удалить reminder через ту же форму.
4. Создать два одноразовых напоминания на ближайшее будущее. Первое проверить
   с закрытой PWA, второе — с открытой PWA на «Моё»/другом ритуале. Тап должен
   открыть выбранный ритуал в одном окне, закрыв старую форму. Проверить и
   повторный тап, когда целевой ритуал уже открыт. Учитывать шаг Cron 5 минут.
   Debug-URL остаётся для разработчика: открытие его отдельно в Safari на iOS
   может использовать другое хранилище, чем установленная PWA.
5. Посмотреть Сегодня, Календарь, Ритуалы, Моё и Уведомления. Главное действие
   ритуала — «Поколдовано»; backup/update/debug не конкурируют с ним.

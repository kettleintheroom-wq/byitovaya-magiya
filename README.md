# Бытовая магия — PWA-прототип

Статическое приложение на HTML, CSS и vanilla JavaScript. Не требует сборки, сервера приложения, регистрации или платных сервисов. Рабочая ветка: `pwa-prototype`. В `main` изменения можно переносить только после проверки и явного согласия владельца проекта.

## Что реализовано

- Четыре экрана: Сегодня, Календарь, Ритуалы, Моё; нижняя навигация.
- Сводка по дню недели, числу месяца, специальной дате и лунным правилам. Совпавшие события показываются вместе.
- Все 26 исходных ритуалов, тексты, категории и правила сохранены. Практики лунной фазы сгруппированы отдельно; постоянные приметы доступны в библиотеке.
- Месячный календарь: предыдущий/следующий месяц, выбор дня, возврат к сегодняшнему дню, отметки событий и лунных практик.
- Поиск по названию, описанию, реквизиту и категории; фильтры.
- Карточки: реквизит, описание, исходная инструкция, фразы, происхождение, сохранить, Поколдовано, поделиться. Можно задать отдельный массив `steps`; иначе исходная инструкция разбивается по предложениям, без добавления действий.
- Избранное, журнал выполнений (не более одной отметки на ритуал за день), отмена отметки, статистика за месяц, onboarding и настройки в localStorage.
- Импорт старого журнала `bbm-v5` при первом открытии на том же адресе, если нового журнала ещё нет.
- Дата обновляется после полуночи и при возврате в приложение.
- Manifest, service worker, PNG-иконки 192/512, maskable-иконка, Apple Touch Icon, standalone, safe areas.
- Offline-кеш интерфейса, календарного движка и всех ритуалов после успешной первой загрузки.
- Установка: нативное предложение там, где браузер предоставляет его, иначе инструкция. iPhone: инструкция для Safari.
- Web Share API; резервный вариант — копирование текста со ссылкой или окно для ручного копирования.
- Проверка обновления; новая версия ожидает нажатия «Обновить». Локальные данные при обновлении не удаляются.
- Экспорт журнала в JSON (архивная копия; автоматического импорта этой копии в MVP нет).

## Ограничения

Нет аккаунтов, синхронизации между телефонами, push-уведомлений, платежей, backend и AI-гаданий. Данные preview и production раздельные, потому что адреса разные. Некоторые браузеры также разделяют данные Safari и установленного приложения: пользоваться лучше установленной версией. Локальное хранилище может быть очищено пользователем или системой; это не облачное резервирование. Лунный расчёт приблизительный, перенесён из исходного проекта; даты определяются по часовому поясу устройства. Условные приметы («перед дорогой» и т. п.) не назначаются каждому дню, поскольку приложение не знает обстоятельств человека. Offline работает только после загрузки с интернетом. Нативное окно установки и отправки зависит от браузера. Проверка на физическом iPhone/Android остаётся отдельным приёмочным этапом.

## 2. Где хранится контент

Сейчас сделай это: открой репозиторий GitHub, в переключателе веток выбери `pwa-prototype`, затем открой `rituals.js`.

В начале файла находятся названия источников `OR` и категорий `CAT`. Далее массив `rituals`: одна запись между `{` и `}` — один ритуал. `id` — постоянный идентификатор для избранного и истории; уже существующие `id` менять не следует.

## 3. Как добавить ритуал

Сначала нужен подтверждённый материал о существующей практике. Не записывайте придуманные игровые действия как народные традиции.

Сейчас сделай это: в ветке `pwa-prototype` открой `rituals.js`, нажми значок карандаша. Перед последней строкой `];` добавь запись по следующему шаблону, заменив значения подтверждённым содержанием. Между соседними записями должна быть запятая.

```js
{
  id:"new-unique-id",        // уникальный ID латиницей, без пробелов
  no:"027",                // следующий номер
  title:"Название",
  icon:"✳",                // простой чёрный знак
  cat:["luck"],            // одна или несколько существующих категорий
  origin:"folk",           // классификация источника
  time:"anytime",          // без календарной привязки
  when:"Когда выполнять",
  short:"Краткое описание",
  need:"Что понадобится",
  do:"Исходная инструкция.",
  steps:["Первый шаг.","Второй шаг."], // необязательно; те же действия подробнее
  say:"Что говорить или «Не требуется».",
  act:"Выполнить ритуал",
  done:"Поколдовано"
}
```

Категории: `money` — деньги, `love` — любовь, `luck` — удача, `home` — дом, `work` — работа, `moon` — Луна. Источники: `folk`, `internet`, `simoron`, `esoteric`, `tradition`, `fengshui`. Источник присваивается по содержанию, не наугад.

Для расписания добавьте `rule` и подходящий `time`:

| `rule` | Когда срабатывает |
|---|---|
| `thursday` | Каждый четверг |
| `friday` | Каждую пятницу |
| `first` | Первое число каждого месяца |
| `newyear` | 31 декабря |
| `newmoon` | День новолуния |
| `fullmoon` | День полнолуния |
| `waxing` | Растущая фаза |
| `waning` | Убывающая фаза |

Для другого конкретного числа или дня нужна новая ветка проверки в `matchRule` в `calendar.js`. Один лишь текст в `when` не назначает событие календарю. У новой записи с существующим `rule` календарь начнёт работать автоматически; добавлять ID в старый `CALENDAR_RITUAL_IDS` не требуется. Этот набор сохранён для сравнения исходной логики.

Сейчас сделай это: после изменения обнови номер версии по пункту 15 и проверь preview. Если не уверена в запятых или новом правиле, передай файл на проверку в Work.

## 4. Как изменить текст

Сейчас сделай это: открой `rituals.js` в `pwa-prototype`, нажми карандаш, найди ритуал по `title`, измени нужное поле внутри кавычек. Сохрани кавычки и запятые. Внутренние двойные кавычки лучше заменить русскими «ёлочками».

Тексты экранов находятся в `app.js`, короткие служебные тексты и название — в `index.html`. Название установленного приложения также есть в `manifest.webmanifest`.

## 5. Как изменить дизайн

Сейчас сделай это: открой `app.css`. В первой строке `:root` находятся цвета: `--bg` (фон), `--ink` (текст), `--pink`, `--blue`, `--orange`, `--yellow`. Меняй нужный HEX-код, например `#ff4db8`.

Размеры заголовков заданы в `h1`, `h2`, `h3`; навигация — в `.bottom`; карточки — `.ritual-card`; главный блок — `.hero`. Для фонового цвета приложения также согласуй `theme_color` и `background_color` в manifest и `theme-color` в `index.html`. Увеличивать кнопки можно, уменьшать их ниже 44–48 px не стоит.

## 7. Как отправить изменения в GitHub

Без терминала и Git:

Сейчас сделай это: для небольшой правки открой файл на GitHub в ветке `pwa-prototype`, нажми карандаш, внеси правку, нажми **Commit changes**, напиши коротко, что изменилось, выбери **Commit directly to the pwa-prototype branch**, подтверди.

Для нескольких локально изменённых файлов:

Сейчас сделай это: установи **GitHub Desktop** с официального сайта и войди в свой GitHub. Выбери **File → Clone repository → URL**, вставь URL репозитория. В **Current branch** выбери `pwa-prototype`. Скопируй изменённые файлы в папку этой копии репозитория. В списке изменений проверь файлы, введи сообщение в **Summary**, нажми **Commit to pwa-prototype**, затем **Push origin**.

Не переключайся на `main` для экспериментальных правок. После каждого изменения файлов приложения подними версию в двух местах по пункту 15.

## 8. Автоматический деплой Cloudflare Pages

GitHub хранит файлы. Cloudflare следит за выбранными ветками. Отправка изменений в `main` запускает production-деплой; отправка в `pwa-prototype` может запускать отдельный preview-деплой, если разрешены preview-ветки.

Сборка этому проекту не нужна. Существующую работающую конфигурацию сохраняй. Если придётся настроить заново: framework — None; build command — пусто; output directory — корень проекта (в интерфейсах, где обязательное поле, `/`); production branch — `main`.

## 9. Как открыть preview

Сейчас сделай это: открой Cloudflare Dashboard → **Workers & Pages** (либо **Compute → Workers & Pages**) → проект `bytovaya-magiya` → **Deployments**. Найди успешный деплой с веткой **pwa-prototype** и окружением **Preview**. Открой его URL и отправь его на телефон.

Проверяй именно URL, показанный Cloudflare; не угадывай адрес. У Cloudflare обычно есть уникальная ссылка конкретного деплоя и адрес ветки, который обновляется. Для нескольких дней использования удобнее адрес ветки; он должен быть показан в карточке деплоя.

Если preview не появился:

Сейчас сделай это: открой настройки проекта → **Builds & deployments / Branch control** (названия могут отличаться), найди **Preview deployments**, разреши ветку `pwa-prototype`. Production branch оставь `main`. Затем в Deployments нажми **Retry deployment**, если для этой ветки уже есть запись. Если записи нет, внеси маленькую правку в README на ветке `pwa-prototype` и отправь её: новый коммит запустит деплой.

Не переноси код в main только ради preview. Если включена защита preview через Cloudflare Access, проверь, что после входа ресурсы `manifest.webmanifest` и `sw.js` тоже загружаются. Для полноценной установки удобен доступный HTTPS-preview без авторизации каждого ресурса.

Сейчас сделай это: убедись, что сохранилась текущая production-версия в истории GitHub, а preview прошёл проверку. В GitHub открой pull request `pwa-prototype → main`. Проверь вкладку **Files changed**: это файлы приложения, инструкция и проверки. Когда решишь публиковать, нажми **Ready for review** у draft PR, затем **Merge pull request → Confirm merge**.

Браузер решает, когда показать системное предложение. Инструкция остаётся доступной всегда; отсутствие автоматической кнопки не означает поломку. После установки открой иконку и проверь отдельный запуск без обычной браузерной панели.

## 14. Проверка offline

Сейчас сделай это: с интернетом открой установленное приложение, перейди в «Моё» и дождись «Запас загружен: интерфейс и ритуалы доступны без сети». Затем включи авиарежим и отдельно выключи Wi-Fi. Полностью закрой приложение и снова открой по иконке.

Проверь календарь, поиск и карточки; сохрани ритуал и отметь «Поколдовано»; снова закрой и открой. Всё должно сохраниться. Верни интернет. Делиться через внешние приложения без сети можно только если само внешнее приложение это поддерживает; проверка обновлений без сети невозможна.

Для технической проверки в Chrome: F12 → **Application → Service Workers**, проверь регистрацию `sw.js`; **Cache Storage** — кеш `bbm-shell-1.0.0` (или текущая версия). В **Network** выбери **Offline**, перезагрузи страницу. Manifest виден в **Application → Manifest**.

## 15. Как обновляется service worker

Service worker — маленький файл, который хранит offline-версию. Для согласованного обновления интерфейс и файлы берутся из кеша одной версии. Новая версия устанавливается в фоне и показывает плашку «Есть свежая версия»; нажатие «Обновить» активирует её и перезагружает приложение. Журнал и избранное находятся отдельно и не очищаются.

Сейчас сделай это: при изменении HTML, CSS, JS, контента или иконок увеличь **обе** версии одинаково: `APP_VERSION` в `app.js` и `VERSION` в `sw.js`, например с `1.0.0` на `1.0.1`. Отправь изменённые файлы вместе. Без смены версии новый offline-кеш может сохранить старые ресурсы.

Сейчас сделай это: после деплоя открой приложение с интернетом, в «Моё» нажми **Проверить обновление**. Если появится плашка, нажми **Обновить**. Номер версии в «Моё» должен стать новым. Если обновление находит браузер при запуске, плашка появится без ручной проверки.

## 16. Если телефон показывает старую версию

Сейчас сделай это: проверь, что открыта нужная ссылка — preview ветки или production, и соответствующий деплой в Cloudflare завершился успешно. Подключи интернет, открой «Моё», нажми «Проверить обновление», затем «Обновить» в плашке.

Если не помогло:

Сейчас сделай это: проверь, что номера в `app.js` и `sw.js` действительно увеличены и совпадают. Полностью закрой приложение, открой снова с интернетом и повтори проверку.

Если всё ещё старая версия:

Сейчас сделай это: сначала скачай копию журнала в «Моё». На компьютере можно открыть F12 → Application → Service Workers → **Unregister** для этого адреса, удалить только кеши `bbm-shell-*` в Cache Storage, затем перезагрузить. Не нажимай **Clear site data**: это может стереть избранное и журнал.

Удаление данных сайта, удаление установленного приложения и его повторная установка на телефоне — крайняя мера: возможна потеря локального журнала. Экспорт сейчас служит читаемой резервной копией; кнопки автоматического восстановления из неё в MVP нет. Лучше сначала проверить номера версий и URL деплоя.

# Бытовая магия 1.2.0 — запуск preview на Windows

Инструкция ниже предназначена для первого запуска и восстановления настройки. На 15.10.2026 владелец уже подтвердил успешный запуск на Windows и публикацию preview Worker и D1. После синхронизации исходников с GitHub повторять setup для обычного auto-deploy не нужно. Доставка на телефон пока требует проверки.

## Перед запуском

1. Распакуйте ZIP полностью в отдельную папку. Не запускайте файлы прямо из архива.
2. Нужен Node.js LTS версии 22 или новее: https://nodejs.org/. После установки откройте новое окно PowerShell.
3. В Cloudflare откройте Workers & Pages → Plans и проверьте, что выбран **Workers Free**. Если выбран Paid, остановитесь: сначала нужно согласовать возможные расходы. Сам скрипт тариф не меняет и тариф по API не проверяет.
4. Смените пароль Cloudflare, который был отправлен в переписке. Скрипт его не использует: вход выполняется через официальный браузерный OAuth.

## Запуск

Откройте распакованную папку, затем папку **push**. В адресной строке Проводника напишите `powershell` и нажмите Enter. Выполните по очереди:

```powershell
npm.cmd ci
node scripts/setup-preview.mjs
```

`npm ci` должен завершиться успешно. При ошибке не запускайте вторую команду, пришлите текст ошибки без паролей и ключей.

На вопросы скрипта:

- `FREE` — только если действительно проверен тариф Workers Free.
- `LOGIN` — откроется вход в Cloudflare в вашем обычном браузере. Войдите в существующий аккаунт и подтвердите Wrangler. Если уже авторизованы локально, можно `SKIP`.
- Скопируйте **Account ID** нужного аккаунта из вывода `whoami` и вставьте его в терминал. Это не пароль.
- `PREVIEW` — разрешает публикацию клиента только в Pages-ветку `pwa-prototype` существующего проекта `byitovaya-magiya`.

Скрипт:

1. Находит или создаёт D1 `byitovaya-magiya-push-preview-db` и применяет SQL-миграцию.
2. Публикует Worker `byitovaya-magiya-push-preview` с Cron `*/5 * * * *`.
3. Создаёт VAPID-ключи локально, передаёт закрытый ключ в Cloudflare secret через stdin. Значения ключей в терминал не выводит.
4. Записывает публичную конфигурацию клиента и публикует только разрешённые файлы интерфейса. Backend, тесты и секреты в Pages не загружаются.
5. Выводит несекретный итог и сохраняет его в `push/deployment.local.json`.

Если Cloudflare попросит выбрать поддомен workers.dev или принять новые условия, завершите это самостоятельно в своём аккаунте. Если публикация остановилась, сохраните папку и повторите запуск после устранения причины. Уже созданная D1 будет использована повторно. **Не удаляйте `push/.secrets/vapid.json`**: повторный запуск должен использовать те же ключи. Если Worker уже содержит ключи, а локального файла нет, скрипт остановится без их замены.

Ни `main`, ни GitHub PR скрипт не изменяет. Он не создаёт production-окружение. Локальная папка не содержит git-историю. Если позже переносите изменения в GitHub, делайте это только в `pwa-prototype`; не загружайте `.secrets`, `.wrangler`, `node_modules`, `wrangler.local.json` и `deployment.local.json`.

## После успешного запуска

Пришлите только итоговый JSON из терминала или файл `push/deployment.local.json`. Он содержит URL и названия ресурсов, без секретов. Не присылайте `.secrets`, `.dev.vars` или файлы авторизации Wrangler.

На iPhone:

1. Откройте уже установленную PWA на постоянном preview-адресе. «Моё» → «Проверить обновление» → «Обновить». Должна появиться версия **1.2.0**. Удалять приложение, очищать Safari и переустанавливать его не нужно. Проверьте старый журнал и избранное.
2. «Моё» → «Уведомления». До подключения видны пять наборов; можно заранее выключить любой. Нажмите «Включить уведомления» и разрешите уведомления в системном окне. Если приложение открыто в обычном Safari, сначала добавьте его на главный экран по инструкции.
3. Дождитесь «Подписка создана. Настройки подтверждены сервером». Нажмите «Отправить тестовый push». Ответ «Push-сервис принял тест» означает приём сервисом доставки, а не гарантию появления на телефоне. Сверните PWA, проверьте уведомление и нажмите его: должен открыться кофе с корицей. Повторите с уже открытой PWA. Тест доступен раз в минуту.
4. Выключите «Красное бельё по пятницам» и дождитесь подтверждения сервера. Остальные наборы останутся включены.
5. Откройте любой ритуал → «Своё напоминание» → «Каждую неделю», выберите день и время. Сохраните; оно появится в «Моих напоминаниях». Затем проверьте изменение и удаление.
6. Создайте другое напоминание «Один раз» минимум через 10 минут. Cron проверяет очередь каждые 5 минут; доставку может дополнительно задержать система телефона. После принятия отправки оно исчезает из активного списка при следующем открытии приложения. Дождитесь ещё двух запусков Cron и убедитесь, что повтор не пришёл.
7. «Отключить уведомления» → дождитесь подтверждения. Расписания и выбранные наборы сохранятся. Без сети отключение только ставится в очередь: сервер использует старые настройки, пока изменение не подтверждено.

Полные технические детали, ограничения и результаты тестов: `docs/UPDATE-1.2.0.md`.
